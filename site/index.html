Better Claude
What it does Limits Source

macOS app

Move a Claude conversation to wherever you are working.

Better Claude operates on the conversation stores that Claude Desktop and Claude Code already keep on your Mac. Move a chat between installs. Fork it at any message. Find every file Claude ever wrote for you. Your conversations never leave the machine.

Download for macOS Read the source

Requires macOS 14 or later. The build is not notarised, so the first launch needs a right-click and Open — that and the rest of the trade-offs are below. You can also build from source with Xcode's Swift toolchain: ./Scripts/make-app.sh.

Four things it does

01

Transfer a conversation, with the chat intact.

Pick a conversation in one Claude Desktop install and send it to another, or into a Claude Code project. User turns, assistant turns, tool calls, and inline images and documents all arrive. You see a plan first — every check, every path that will be created — and nothing is written until you confirm.

Verified by comparing per-message SHA-256 fingerprints. Every message and every inline image or document is byte-identical in all three directions.

02

Control what every install is running.

Better Claude inventories every skill, MCP server, subagent, slash command, hook and memory file across every install on the machine, then diffs two installs against each other so you can see what one has that the other does not. It is read-only. It reports; it changes nothing.

215 configuration items across 16 scopes on the developer's own machine — one global Claude Code config, ten projects, and five Desktop installs.

03

Keep a library of everything Claude produced.

Every code block, generated file and upload, deduplicated by content hash, each one carrying provenance back to the conversation it came from. The script you half-remember from three weeks ago becomes findable.

699 artifacts, 178.9 MB, across 102 conversations, with 90 duplicates collapsed — on one real machine, in about a second.

04

Branch a conversation at any message.

Choose a message and fork the conversation there into a new one. The original stays as it was. Neither Claude app can do this. The fork follows the parentUuid chain rather than line order, so its ancestry is intact rather than merely plausible.

And the smaller things

Search every conversation on the machine
Reads every transcript once, across every install and every Claude Code project, and ranks whole conversations with the matching passages underneath as evidence.
Read without launching Claude
Open any conversation in the app, with inline Markdown, code blocks, and its own search.
Export to Markdown
Speakers, timestamps and prose, with the tool plumbing left behind.

What it does not do

These are the constraints worth knowing before you install it. Most of them are structural; the notarisation one is a purchase away.

macOS only, macOS 14 or later
The store layout and the running-process checks are both platform-specific.
Not sandboxed, and therefore not on the Mac App Store
A sandboxed app cannot read another app's data directory, which is the whole job. That trade is not available to take back.
The on-disk format is undocumented and moves
It was derived by reading real sessions, and it demonstrably changes between Claude releases. Session data is therefore never modelled with fixed structs: unknown fields are preserved untouched rather than dropped.
Credentials, audit logs and permission grants are never exported
The credential scan runs on the assembled export rather than on the source, so a redaction bug in the assembler cannot pass it. A hit blocks the export and names the file and the rule, never the matched value.
Imports create; they never overwrite
Every import writes a receipt listing exactly what it created, and any import can be undone. The undo refuses to delete anything you have edited since.
Ad-hoc signed, not notarised
A downloaded build arrives quarantined, so Gatekeeper blocks the first launch: right-click the app and choose Open, once per version. The in-app updater checks each download against a SHA-256 published with the release, which catches tampering in transit but not a compromised release account — the archive and its checksum are published by the same one.
A destination install must have been signed into once
Claude Desktop only ever reads the account it is signed into, so a conversation filed under any other account is invisible rather than broken. Model availability is not checked either: a conversation that used a model the destination does not offer still imports, and the destination picks one when you continue it.
Verified against one machine's data
The path encoder is checked against every project directory present there, and transfers are verified by comparing per-message checksums — but this has not been tested across many accounts or Claude versions. The figures above come from that same machine.

Works best with Parallex

Parallex runs multiple fully isolated instances of any macOS app, each with its own Dock icon, its own data, and its own settings.

The pairing is not a cross-promotion. Parallex is what creates several isolated Claude installs in the first place — a personal one, a work one, a second account, each genuinely separate on disk. Better Claude is what moves work between them. One makes the installs; the other makes them a single workspace. Neither needs the other, and each is more useful with it.

Get it

One download, no account, no telemetry. The app reads directories that are not in a privacy-protected category, so there is nothing to allow in System Settings and Full Disk Access is not required. The only request it ever makes is to GitHub, when you ask it to check for an update.
